# Face Reg — จดจำใบหน้าด้วย JavaScript

เว็บเดโมสำหรับลงทะเบียนใบหน้าและเทียบกับรายชื่อที่บันทึกไว้ โดยใช้กล้องและประมวลผลในเบราว์เซอร์ด้วย `@vladmandic/face-api` รุ่น `1.7.15` โค้ดหน้าเว็บเป็น HTML, CSS และ JavaScript ส่วน Node.js ทำหน้าที่เสิร์ฟไฟล์บนเครื่องเท่านั้น

## เริ่มใช้งาน

ต้องมี Node.js 20.11 ขึ้นไปและ npm เปิด PowerShell ในโฟลเดอร์โปรเจกต์ แล้วรัน:

```powershell
cd 'K:\!WORK\face-reg'
npm install --ignore-scripts
npm start
```

เปิด **http://127.0.0.1:5188** ใน Chrome หรือ Microsoft Edge แล้วอนุญาตให้เว็บใช้กล้อง ต้องเปิดผ่านที่อยู่ loopback บนเครื่อง เช่น `127.0.0.1` หรือผ่าน HTTPS; การดับเบิลคลิก `index.html` โดยตรงใช้ไม่ได้

ควรใช้ URL ที่เซิร์ฟเวอร์พิมพ์ให้ตรงตามนั้น ชื่อ `localhost` อาจชี้ไป IPv6 และเปิดแอปอื่นที่ใช้พอร์ตเดียวกันอยู่ ส่วนเซิร์ฟเวอร์นี้รับการเชื่อมต่อทาง `127.0.0.1` เท่านั้น

`npm install` ปกติก็ใช้ได้ โปรเจกต์นี้ไม่ต้องอาศัย install lifecycle scripts การเริ่มเซิร์ฟเวอร์จะคัดลอกไลบรารีและโมเดลที่จำเป็นจาก `node_modules` มาไว้ใน `public` โดยอัตโนมัติ หลังติดตั้งและเตรียมไฟล์ครบแล้ว การจดจำใบหน้าไม่ต้องเรียก CDN หรือบริการคลาวด์และใช้งานโดยไม่มีอินเทอร์เน็ตได้

## วิธีใช้งาน

1. รอให้โหลดโมเดลสำเร็จ แล้วเปิดกล้อง
2. ให้มีใบหน้าเพียงคนเดียวอยู่ในภาพ ตั้งชื่อบุคคล และยืนยันความยินยอมให้บันทึกข้อมูลใบหน้า จากนั้นเก็บตัวอย่าง **3 ครั้งของคนเดียวกัน** โดยขยับมุมหรือสีหน้าเล็กน้อย ใช้แสงที่สม่ำเสมอ
3. บันทึกบุคคล จากนั้นเริ่มจดจำ ระบบจะเทียบใบหน้ากับรายชื่อที่บันทึกไว้
4. หากไม่พบใบหน้าในระยะที่กำหนด ระบบจะแสดงว่าไม่รู้จัก สามารถลบรายบุคคลหรือล้างข้อมูลทั้งหมดได้จากส่วนรายชื่อ

ค่าเริ่มต้นของเกณฑ์ระยะห่าง (distance threshold) คือ **0.50** ค่ายิ่งต่ำยิ่งเข้มงวดและอาจไม่รู้จักใบหน้าที่ควรตรงกัน ค่าสูงขึ้นยอมรับความแตกต่างได้มากขึ้นแต่เพิ่มโอกาสจับคู่ผิด ระยะห่างไม่ใช่เปอร์เซ็นต์ความแม่นยำ

## ข้อมูลที่จัดเก็บ

แอปเก็บชื่อและเวกเตอร์ลักษณะใบหน้า (face descriptors/templates) ใน `localStorage` ของเบราว์เซอร์บน origin ปัจจุบัน ไม่เก็บภาพถ่ายและไม่มี API อัปโหลดภาพหรือข้อมูลไปคลาวด์ เทมเพลตยังถือเป็นข้อมูลอ่อนไหว ควรใช้กับผู้ที่ยินยอมให้ลงทะเบียนและลบข้อมูลเมื่อไม่ต้องใช้แล้ว

การลบรายชื่อในแอปจะลบเทมเพลตนั้นออกจาก `localStorage` หรือใช้การล้างข้อมูลเว็บไซต์ของเบราว์เซอร์เพื่อลบทั้งหมด ข้อมูลไม่ข้ามเบราว์เซอร์หรือพอร์ต เช่น `127.0.0.1:5188`, `127.0.0.1:5189` และ `localhost:5188` เป็นคนละ origin จึงมีรายชื่อแยกกัน ในโหมดไม่ระบุตัวตนข้อมูลอาจหายเมื่อปิดหน้าต่าง

## คำสั่งเพิ่มเติม

```powershell
npm run dev             # เหมือน npm start
npm run prepare:assets  # คัดลอกไลบรารีและโมเดลจาก node_modules อีกครั้ง
npm test                # ทดสอบการจับคู่/จัดเก็บข้อมูล การเสิร์ฟไฟล์ และการเตรียมโมเดล
npm run build           # สร้างเว็บพร้อมโมเดลใน dist/
```

หากพอร์ต 5188 ถูกใช้งานอยู่ ให้หยุดเซิร์ฟเวอร์เดิมหรือเปลี่ยนพอร์ต:

```powershell
$env:PORT = '5189'
npm start
```

จากตัวอย่างนี้ให้เปิด **http://127.0.0.1:5189** เซิร์ฟเวอร์รับการเชื่อมต่อเฉพาะ `127.0.0.1` กด `Ctrl+C` เพื่อหยุด ไม่มีการเปิดให้เครื่องอื่นในเครือข่ายใช้งานโดยอัตโนมัติ ไฟล์ใน `dist/` ใช้กับ static web server ที่รองรับที่อยู่ loopback หรือ HTTPS ได้

## โครงสร้าง

```text
public/
  index.html          หน้าเว็บ
  styles.css          รูปแบบหน้าจอ
  js/                 โค้ดกล้อง ลงทะเบียน จดจำ และจัดเก็บข้อมูล
  vendor/             ไลบรารีที่คัดลอกจาก npm (สร้างอัตโนมัติ)
  models/             โมเดลที่จำเป็น 3 ชุด (สร้างอัตโนมัติ)
scripts/
  server.js           static server พร้อมตรวจเส้นทางไฟล์
  prepare-assets.js   เตรียมโมเดลและไลบรารีภายในเครื่อง
  build.js            สร้าง dist/
test/                 ชุดทดสอบด้วย node --test
```

ใช้โมเดล `tiny_face_detector`, `face_landmark_68` และ `face_recognition` เท่านั้น ไฟล์ manifest เป็นตัวระบุ shard ที่ต้องคัดลอก จึงไม่ต้องดาวน์โหลดโมเดลด้วยมือ

## แก้ปัญหาเบื้องต้น

- **เปิดกล้องไม่ได้:** ตรวจสิทธิ์กล้องในเบราว์เซอร์และ Windows ปิดแอปที่กำลังใช้กล้อง และเปิดด้วย URL `http://127.0.0.1:5188` ที่เซิร์ฟเวอร์พิมพ์ให้ หรือใช้ HTTPS
- **ไม่พบโมเดลหรือไลบรารี:** รัน `npm install --ignore-scripts` ตามด้วย `npm run prepare:assets` แล้วรีเฟรชหน้า
- **ตรวจไม่พบใบหน้าหรือจับคู่ไม่ตรง:** เพิ่มแสง มองกล้อง ให้ใบหน้าชัดและไม่มีคนอื่นในเฟรม แล้วเก็บตัวอย่างใหม่
- **รายชื่อหาย:** ตรวจว่าใช้เบราว์เซอร์และ URL รวมถึงพอร์ตเดิม และไม่ได้ล้างข้อมูลเว็บไซต์

## ข้อจำกัด

นี่เป็นเดโมสำหรับเรียนรู้และทดลอง ไม่ได้ทำ liveness detection จึงอาจถูกหลอกด้วยภาพหรือวิดีโอ และยังไม่เหมาะใช้เป็นระบบยืนยันตัวตนหรือควบคุมการเข้าออกที่ต้องการความปลอดภัยสูง ผลลัพธ์ขึ้นกับกล้อง แสง มุมใบหน้า และข้อมูลที่ลงทะเบียน
